# Contributing

## Philosophy

The project should be developed in the open from its earliest stages.

Contributions are welcome in:

-   scientific methods;
-   software engineering;
-   documentation;
-   examples;
-   tests;
-   benchmarks;
-   datasets;
-   issue reports;
-   scientific review.

## Before opening a pull request

Please:

1.  search existing issues;
2.  explain the motivation;
3.  keep changes focused;
4.  add or update tests;
5.  update documentation;
6.  describe scientific assumptions;
7.  update the changelog when appropriate.

## Scientific contributions

A pull request implementing a scientific method should include:

-   references;
-   mathematical definition;
-   assumptions;
-   validation strategy;
-   limitations;
-   comparison with existing implementations where possible.

## API changes

Public API changes should be discussed before implementation.

Breaking changes require explicit justification.

## Issues

Use issues for:

-   bugs;
-   feature requests;
-   scientific questions;
-   documentation problems;
-   reproducibility problems.

A bug report should include a minimal reproducible example whenever
possible.

## Discussions

Use discussions for:

-   architectural questions;
-   proposed scientific directions;
-   interpretation of standards;
-   roadmap proposals.

## Code review

Reviewers should assess:

-   correctness;
-   tests;
-   API clarity;
-   documentation;
-   numerical stability;
-   scientific validity;
-   maintainability.

## Attribution

Contributors should receive appropriate credit.

When a contribution is substantial to the scientific software,
authorship or formal acknowledgement should be discussed transparently.
