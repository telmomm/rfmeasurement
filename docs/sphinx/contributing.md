# Contributing to rfmeasurement

`rfmeasurement` is developed in the open from its earliest stages.
Contributions are welcome in scientific methods, software engineering,
documentation, examples, tests, benchmarks, datasets, issue reports, and
scientific review.

## Practical mechanics

The step-by-step guide (getting set up, running the tests, what a pull
request should contain, code style) lives in
[`CONTRIBUTING.md`](https://github.com/telmomm/rfmeasurement/blob/main/CONTRIBUTING.md)
at the repository root.

## Scientific contributions

A pull request implementing a scientific method (a validation rule, an
uncertainty model, a propagation algorithm) should additionally include
references, the mathematical definition, assumptions and limitations, and a
validation strategy. See
[`docs/contributing.md`](https://github.com/telmomm/rfmeasurement/blob/main/docs/contributing.md)
for the full philosophy behind this requirement.

## Reporting bugs and asking questions

Use the [issue tracker](https://github.com/telmomm/rfmeasurement/issues) for
bugs, feature requests, and scientific questions, and
[GitHub Discussions](https://github.com/telmomm/rfmeasurement/discussions)
for open-ended architectural or scientific-direction questions.

## Governance

Decisions are recorded as
[Architecture Decision Records](https://github.com/telmomm/rfmeasurement/tree/main/docs/adr),
and the project's decision-making process is documented in
[`docs/governance.md`](https://github.com/telmomm/rfmeasurement/blob/main/docs/governance.md).

## Code of conduct

This project follows the
[Contributor Covenant](https://github.com/telmomm/rfmeasurement/blob/main/CODE_OF_CONDUCT.md).
